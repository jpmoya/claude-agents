# claude-agents

JP's shared Claude Code config, synced across machines (Mac + Clog VM). Despite the name it now holds everything global, not just agents.

| Path | Symlinked to | Contents |
|---|---|---|
| `agents/` | `~/.claude/agents` | pipeline agent definitions |
| `hooks/` | `~/.claude/hooks` | hook scripts (all cross-platform; `cap-heavy-commands.py` is VM-only and wired from the VM's local settings if wanted) |
| `skills/` | `~/.claude/skills` | user skills |
| `CLAUDE.md` | `~/.claude/CLAUDE.md` | global instructions |
| `settings.json` | `~/.claude/settings.json` | shared settings: permissions, cross-platform hooks, skillOverrides, marketplaces, effort/advisor |

**Machine-specific settings stay in `~/.claude/settings.local.json`** (not tracked): model, theme, tui, plugin toggles, notification-sound hooks, `outputStyle`, `disabledMcpjsonServers`. Claude Code merges it over `settings.json`. Secrets never go here — `~/.claude/mcp-servers/`, `.mcp.json`, memory and `~/.claude.json` stay local.

- A `SessionStart` hook (`hooks/sync-agents.sh`) runs `git pull --ff-only` here, so every session starts with the latest config, and prints a warning if any symlink has been replaced by a real file.
- To change anything: edit here (or through the symlink), commit, push. Other machines pick it up on their next session.
- **No repo-local agents.** A repo's `.claude/agents/` holds at most `deployer.md`, which the orchestrator looks for locally. Nothing else: project-level agents override user-level ones, so a local `code-reviewer` silently replaces the pipeline one, and a repo-prefixed fork drifts from the global definition (casa-verde-site's did, 2026-09-03). Repo-specific rules go in that repo's `CLAUDE.md`, which every global agent reads.

## Install on a new machine

```bash
git clone https://github.com/jpmoya/claude-agents.git ~/dev/claude-agents   # VM: ~/claude-agents
cd ~/.claude && mkdir -p backups/pre-dotfiles && mv agents hooks skills CLAUDE.md settings.json backups/pre-dotfiles/ 2>/dev/null
R=~/dev/claude-agents; for i in agents hooks skills CLAUDE.md settings.json; do ln -s $R/$i ~/.claude/$i; done
# then put machine-specific keys in ~/.claude/settings.local.json
```

Pipeline: product-manager → ux-flow-designer (UI tickets: user flow — screens, states, copy) → ui-ux-designer (UI tickets: mockups of that flow, JP approval gate) ∥ solutions-architect (architecturally significant tickets) → **test-writer** (failing tests + stubs from the ACs, committed to the feature branch) → **test-reviewer** (pre-implementation: AC coverage, falsifiability) → fullstack-developer (implements against the locked tests; may add tests in new files, never edits locked ones — enforced by `hooks/protect-locked-tests.sh` + the orchestrator's byte-identical diff) → code-reviewer [+ test-reviewer narrow, only on added tests] → deployer (global; a repo may override with its own `deployer.md`). Staging-model caveat (scheduler and quoting tool, same two-Vercel-project / two-Supabase-project structure): feature branches come off `staging`, PRs target `staging`, the deployer merges to `staging` only — staging migrations, Actions deploy, E2E — and JP promotes `staging` → `main` to production himself; the deployer never touches `main` in those repos. `orchestrator` dispatches stages by reading `**[agent] MARKER**` comments on the GitHub issue. **Comment protocol:** every agent starts every comment with `**[agent] MARKER**` on line 1 — a routing marker for handoffs, `NOTE` for anything else (the orchestrator skips NOTEs). The orchestrator reads first lines only (jq), never the full thread. `hooks/require-handoff-marker.sh` (Stop/SubagentStop) refuses to let a stage finish until its marker is on the issue, using the `PIPELINE_ISSUE/AGENT/REPO` coordinates the orchestrator exports per launch; a no-marker run gets one handoff-only recovery dispatch before it's reported. `orchestrator` and `deployer` run on Sonnet (mechanical stages); the rest inherit the session model. The orchestrator itself is launched headless via `skills/orchestrate` (never as a subagent — `hooks/block-orchestrator-agent.sh` enforces it). A cron-based **supervisor** (`skills/orchestrate/supervisor.sh`, every 2 min on both machines — VM even minutes, Mac odd) does everything in one tick: restarts exited non-terminal orchestrators with backoff (120s/300s/900s/1800s; transient exits get a longer table), drains the local queue, caps at 3 concurrent (memory-aware: 1200MB floor), drops `agent-in-progress` on runs that finished or parked, and — where the machine's untracked `~/.claude/pipeline/config.local.sh` lists `DISPATCH_REPOS` — launches one open `agent-go` issue per tick after winning a claim (a `**[supervisor] NOTE** claim: <host>` comment; earliest in 10 min wins). Label rule: `agent-go` = approved and unlaunched; launching anywhere swaps it for `agent-in-progress`; the supervisor removes that when done/held. The launcher refuses issues owned elsewhere (`--force` overrides). Human gates (MOCKUPS PENDING APPROVAL, AWAITING GO) and BLOCKED past a 20-minute grace park the run as `held` with an alert; escalation after 3 no-progress or 6 total restarts posts a `**[supervisor] NOTE**` and holds too. `orchestrate.sh stop` writes a tombstone preventing auto-restart; a manual relaunch clears tombstones, `.restarts`, and `.alert` files and supersedes a queued entry. Mac dispatch runs only on AC power. Orchestrator processes run with `oom_score_adj=300` (Linux) so the kernel evicts them before interactive sessions. Logs append (`>>`) across restarts with separator lines, so prior-run evidence survives for diagnosis. The drain queue checks tombstones before launching, and `escalate()` purges the queue entry, preventing zombie relaunches of held issues. BLOCKED markers get a 20-minute grace period (`GRACE_PERIOD_SECS=1200`) before being treated as terminal — this prevents false-BLOCKED races where a subagent posts BLOCKED prematurely while its work is still completing (incident: #163, 2026-09-07).

**Fast lane (2026-09-08).** The PM writes a mandatory `Lane: fast | full` and a strict `UI change: yes | no` (back-end-only work is always `no`; the orchestrator never guesses). Fast-lane tickets — bug fixes, small changes, copy/link/config — go product-manager → fullstack-developer in fast-lane mode (writes its own regression test via `fullstack-bug-fixing`) → code-reviewer + test-reviewer narrow on Sonnet → deployer, skipping UX, SA, test-writer and the lock. Stall policy: the orchestrator polls every 15s, stops the moment a stage process dies, and caps a silent live process at 10/15/30 min by stage (one extension if the log is still moving), then kills it and runs handoff recovery.

**Infra track.** Issues labelled `infra` (DNS, Vercel domains/env/redirects, Supabase auth config, webhooks, API keys, workflow config, credential rotation) fork at the orchestrator to a separate roster with the same marker protocol: `infra-planner` (read-only inventory, then a runbook on the issue — per step: command, expected, verify, rollback, env, dependencies) → `infra-reviewer` (checklist review + spot-checks, `PLAN PASS` / `PLAN FAIL: n`) → `infra-operator` (executes verbatim; staging unattended, prod steps wait for JP's `go` comment on the issue; any Verify mismatch runs that step's rollback and posts `BLOCKED`). No tests, no PR, no branch on this track; work needing both code and infra is two issues. Patterns borrowed from davila7/claude-code-templates' bicep-plan/bicep-implement split and terraform-iac-reviewer's plan/apply discipline (2026-09-08).

**Effort tiers (2026-09-08).** Every agent sets `effort:` in its frontmatter, overriding the shared `effortLevel: high` (which stays for interactive sessions): `low` for mechanical stages (orchestrator, deployer, infra-operator), `medium` for spec and checklist stages (product-manager, ux-flow-designer, test-reviewer, infra-reviewer), `high` for design and implementation (solutions-architect, test-writer, fullstack-developer, code-reviewer, infra-planner, ui-ux-designer). Fast-lane reviewer launches add `--effort medium` alongside `--model sonnet`.

Why tests are authored separately: tests written by the implementer inherit its misreading of the spec (AgentCoder, arXiv 2312.13010). Independent authoring plus a mechanical lock means the test review runs once, early, instead of after every fix cycle.
